# Foundly Backend

The backend is a FastAPI REST API with asynchronous SQLAlchemy, PostgreSQL, and Alembic migrations. It uses uv for dependency and environment management.

## Requirements

- Python 3.9 or newer
- uv
- PostgreSQL 15 or newer

## Technology stack

**Runtime dependencies**

- FastAPI
- Uvicorn
- SQLAlchemy with asyncio
- asyncpg
- Alembic
- Pydantic and pydantic-settings
- pwdlib with Argon2
- PyJWT
- python-multipart

**Development dependencies**

- pytest and pytest-asyncio
- httpx
- aiosqlite
- Ruff

## Getting started

```bash
cd backend
cp .env.example .env
uv sync
```

Copy `.env.example` to `.env` and update `DATABASE_URL` and `SECRET_KEY` for your environment. Do not commit `.env`.

| Variable                      | Description                              | Default                                                         |
| ----------------------------- | ---------------------------------------- | --------------------------------------------------------------- |
| `APP_NAME`                    | Application name                         | `Foundly`                                                       |
| `ENVIRONMENT`                 | Runtime environment                      | `development`                                                   |
| `DATABASE_URL`                | Async PostgreSQL connection string       | `postgresql+asyncpg://postgres:postgres@localhost:5432/foundly` |
| `SECRET_KEY`                  | Secret used to sign JWTs                 | `change-me-in-production-use-a-long-random-value`               |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | JWT and cookie lifetime in minutes       | `30`                                                            |
| `CORS_ORIGINS`                | Comma-separated allowed frontend origins | `http://localhost:5173`                                         |
| `COOKIE_SECURE`               | Send the auth cookie only over HTTPS     | `false`                                                         |
| `COOKIE_SAMESITE`             | SameSite policy for the auth cookie      | `lax`                                                           |

## Database setup

Create a local PostgreSQL database:

```bash
createdb foundly
```

The default connection string is:

```text
postgresql+asyncpg://postgres:postgres@localhost:5432/foundly
```

Update `DATABASE_URL` in `.env` if your username, password, host, port, or database name differs.

## Migrations

Alembic configuration is available in `alembic.ini`, with migrations stored in `alembic/`. The initial migration creates the `users` table.

Use:

```bash
# Create a migration after changing models
uv run alembic revision --autogenerate -m "describe the change"

# Apply pending migrations
uv run alembic upgrade head

# Roll back the latest migration
uv run alembic downgrade -1
```

Always review autogenerated migrations before applying them.

## Development

```bash
uv run uvicorn app.main:app --reload
```

The API will be available at `http://localhost:8000`, with interactive documentation at `http://localhost:8000/docs`.

## API

All routes are exposed under `/api/v1`. Authentication uses a JWT stored in an httpOnly cookie named `foundly_access_token`.

| Method | Path                    | Description                                   |
| ------ | ----------------------- | --------------------------------------------- |
| `GET`  | `/api/v1/health`        | Health check                                  |
| `POST` | `/api/v1/auth/register` | Create a user from JSON `{ email, password }` |
| `POST` | `/api/v1/auth/login`    | OAuth2 password form (`username` = email)     |
| `POST` | `/api/v1/auth/logout`   | Clear the auth cookie                         |
| `GET`  | `/api/v1/auth/me`       | Return the current user                       |

Successful responses are returned as raw JSON objects. Errors use FastAPI's standard `{ "detail": ... }` shape.

Set `COOKIE_SECURE=true` in production. If the frontend runs on a different site than the backend, use `COOKIE_SAMESITE=none` together with HTTPS and add CSRF protection.

## uv commands

```bash
uv sync              # Install runtime and development dependencies
uv add <package>     # Add a runtime dependency
uv add --dev <package> # Add a development dependency
uv lock              # Update the lockfile
uv run <command>     # Run a command inside the project environment
```

## Project structure

```text
app/
├── core/           Configuration, security, and shared infrastructure
├── database/       Database engine and session management
├── models/         SQLAlchemy models
├── schemas/        Pydantic request and response schemas
├── routers/        FastAPI route handlers
├── services/       Business logic
└── dependencies/   Reusable FastAPI dependencies

alembic/            Database migrations
tests/              Automated tests
```

Routers should stay thin, with business logic in `services/`. Database access and schema definitions belong in `database/`, `models/`, and `schemas/`.
